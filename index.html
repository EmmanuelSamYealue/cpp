0. Setup & Environment

Before you can compile your first program, you need two things: a compiler (the program that turns your text into an executable) and an editor or IDE (where you type the code). The compiler is separate from the editor — VS Code and Code::Blocks are not compilers themselves; they call a compiler like MinGW-w64 (GCC) behind the scenes.

0.1 The Two Components You Need

ComponentWhat It DoesExamples
Compiler + debuggerTurns .cpp source into an executable; debugs it line by lineGCC (g++), Clang, MSVC
Editor / IDEWhere you type code; can invoke the compiler for youVS Code, Code::Blocks, Visual Studio, CLion

This section walks you through two beginner-friendly setups: VS Code + MinGW-w64 and Code::Blocks with bundled MinGW. Both use the same underlying GCC compiler, so your code will be identical in either.

0.2 VS Code + MinGW-w64 (Windows)

VS Code is a lightweight editor. It does not ship with a C++ compiler, so you must install one separately and point VS Code at it.

Step 1 — Install the compiler (MinGW-w64)

Download MinGW-w64 from the official site or install it through MSYS2. During installation, note the folder that contains g++.exe and gdb.exe (usually ...\mingw64\bin). Add that bin folder to your system PATH environment variable. Open a new terminal and verify:

g++ --version
gdb --version

If both commands print a version number, the compiler is ready.

Step 2 — Install VS Code and the C/C++ extension

Open VS Code, press Ctrl+Shift+X, search for C/C++ (by Microsoft), and install it.

Step 3 — Create .vscode/tasks.json

This file tells VS Code how to build. Replace the command path with the location of your g++.exe:

{
  "version": "2.0.0",
  "tasks": [
    {
      "type": "shell",
      "label": "g++.exe build active file",
      "command": "C:\\MinGW\\bin\\g++.exe",
      "args": [
        "-g",
        "${file}",
        "-o",
        "${fileDirname}\\${fileBasenameNoExtension}.exe"
      ],
      "options": { "cwd": "C:\\MinGW\\bin\\" },
      "problemMatcher": ["$gcc"],
      "group": { "kind": "build", "isDefault": true }
    }
  ]
}

The -g flag adds debug symbols; ${file} and ${fileBasenameNoExtension} are VS Code variables that expand to the current file and its name without extension.

Step 4 — Create .vscode/launch.json

This file tells VS Code how to debug. Set miDebuggerPath to your gdb.exe:

{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "(gdb) Launch",
      "preLaunchTask": "g++.exe build active file",
      "type": "cppdbg",
      "request": "launch",
      "program": "${fileDirname}\\${fileBasenameNoExtension}.exe",
      "args": [],
      "stopAtEntry": false,
      "cwd": "${workspaceFolder}",
      "environment": [],
      "externalConsole": true,
      "MIMode": "gdb",
      "miDebuggerPath": "C:\\MinGW\\bin\\gdb.exe",
      "setupCommands": [
        {
          "description": "Enable pretty-printing for gdb",
          "text": "-enable-pretty-printing",
          "ignoreFailures": true
        }
      ]
    }
  ]
}

The preLaunchTask field connects debugging to the build task from tasks.json, so pressing F5 compiles and then starts the debugger automatically.

Step 5 — Run

Open a .cpp file and press F5 (or click the run button). VS Code builds the file and launches it. You can set breakpoints by clicking in the gutter to the left of a line number.

⚠️ Common problem: 'g++' is not recognized

This almost always means the MinGW bin folder is not on your PATH, or you have not restarted the terminal after changing PATH. Verify with where g++ (Windows) or which g++ (macOS/Linux).

0.3 Code::Blocks (Windows)

Code::Blocks is a full IDE. The easiest installation is the mingw-setup version, which bundles the GCC compiler — you do not need to install the compiler separately.

Step 1 — Download the right installer

On the Code::Blocks download page, choose the file whose name ends in mingw-setup.exe. This includes GCC, GDB, and the toolchain Code::Blocks needs.

Step 2 — Install

Run the installer and press Next through every page, accepting the defaults. This installs Code::Blocks and MinGW into standard locations.

Step 3 — Verify the compiler was detected

Launch Code::Blocks. On first start, it scans the system for compilers automatically. If MinGW was installed in its default directory, it will be found and set as the default compiler with no further action needed.

Step 4 — Check (or fix) the compiler path manually

If you installed MinGW somewhere else, go to Settings → Compiler and Debugger → Global Compiler settings → Toolchain executables. Click Auto-detect; if that fails, click the ... button and select your MinGW installation root directory (not the bin subfolder).

Step 5 — Create and run a project

  1. File → New → Project → Console application → Go.
  2. Choose C++, give the project a name and a folder, and keep the default compiler settings.
  3. Code::Blocks generates a main.cpp with a working "Hello World" program. Press F9 to build and run.

If you prefer not to use a project, you can also create a single .cpp file and press F9 — Code::Blocks will compile and run it directly.

💡 Which should you choose?

Code::Blocks requires fewer manual configuration files and works "out of the box" with the mingw-setup installer — ideal for absolute beginners. VS Code gives you a more modern editing experience, better extension ecosystem, and finer control over build settings. Both use the same GCC compiler underneath, so your code is identical.

1. Introduction to C++

1.1 What Is Programming?

Programming is the process of expressing a solution to a problem as an ordered, unambiguous sequence of instructions that a computer can execute. A program is that sequence; an algorithm is the abstract logic behind it. The programming language is simply the notation you use to communicate the algorithm to the machine.

Three skills matter, in this order:

  1. Problem decomposition — breaking a big problem into small steps.
  2. Algorithmic thinking — expressing those steps precisely (loops, conditions, data).
  3. Syntax — the grammar of the specific language. This is the easiest part, and the part beginners over-focus on.

1.2 What Is C++?

C++ was created by Bjarne Stroustrup at Bell Labs starting in 1979, originally as "C with Classes." It is a compiled, statically typed, multi-paradigm language: it supports procedural programming (like C), object-oriented programming, generic programming (templates), and functional-style techniques.

1.3 Why Use C++?

  • Performance: Zero-cost abstractions — high-level constructs compile down to near-handwritten machine code.
  • Deterministic memory management: You decide when memory is allocated and freed (RAII makes this safe).
  • Portability: Compilers exist for virtually every CPU and OS.
  • Huge ecosystem: Decades of libraries, engines, and tooling.

1.5 Your First Program, Line by Line

// hello.cpp — the smallest complete C++ program
#include <iostream>   // [1] bring in the I/O library
using namespace std;     // [2] make std:: names visible unqualified

int main() {              // [3] program entry point
    cout << "Hello, World!" << endl;  // [4] print + newline
    return 0;             // [5] report success to the OS
}
Output
Hello, World!
PartExplanation
#include <iostream>A preprocessor directive. It textually pastes the contents of the standard I/O header into your file so the compiler knows what cout and endl are. No semicolon is used on #include lines.
using namespace std;Every standard library name lives inside the std namespace. This line lets you write cout instead of std::cout. Convenient for small programs; in larger code prefer explicit std:: qualification.
int main()The entry point. The operating system calls main first. It returns an int — the process exit code.
cout << ...cout ("character output") is the standard output stream. << is the stream insertion operator; each one pushes a value toward the screen.
return 0;0 means "completed successfully." Any non-zero value signals failure and can be read by the shell (echo $?).

1.6 Compiling It

# GCC / Clang (Linux, macOS, MinGW on Windows)
g++ -std=c++17 -Wall -Wextra -O2 hello.cpp -o hello
./hello

# MSVC (Windows, Developer Command Prompt)
cl /EHsc /std:c++17 hello.cpp
hello.exe
💡 Always compile with warnings enabled

-Wall -Wextra (GCC/Clang) or /W4 (MSVC) turns on warnings that catch real bugs: unused variables, signed/unsigned mismatches, uninitialized values, missing returns. Treat warnings as errors during development: -Werror.

⚠️ Two rules that break beginners most often
  • Case sensitivity: cout, Cout, and COUT are three different identifiers. Only the first exists.
  • Semicolons: Every statement ends with ;. Statements that are not statements — #include lines, function definitions, block braces — do not.

2.2 Printing Output with cout

The insertion operator << can be chained arbitrarily. Each operand is converted to text and appended to the output stream in order.

#include <iostream>
using namespace std;

int main() {
    int    age   = 25;
    double price = 19.99;
    string name  = "Alice";

    // Chaining: any number of values, in order
    cout << "Name: " << name
         << " | Age: " << age
         << " | Price: " << price << endl;

    // Multiple statements also work
    cout << "Line one" << endl;
    cout << "Line two" << endl;
    return 0;
}
Output
Name: Alice | Age: 25 | Price: 19.99 Line one Line two

2.3 endl vs "\n" — A Real Performance Difference

Both produce a newline, but they do different amounts of work:

  • "\n" — just inserts the newline character. Cheap.
  • endl — inserts a newline and flushes the stream buffer, forcing an immediate write to the OS. Expensive if repeated.
// SLOW: 100,000 system-level flush operations
for (int i = 0; i < 100000; i++)
    cout << i << endl;

// FAST: buffered, flushed automatically when the buffer fills
for (int i = 0; i < 100000; i++)
    cout << i << '\n';
💡 Practical rule

Use "\n" by default. Reserve endl for the final line before an interactive prompt, where you genuinely need the output visible immediately.

2.5 Namespaces — Why They Exist

Large projects inevitably produce name collisions: your print() and a library's print(). Namespaces create scopes for names.

namespace geometry {
    double area(double r) { return 3.14159 * r * r; }
}

namespace finance {
    double area(double r) { return r * r; } // different formula, same name
}

int main() {
    cout << geometry::area(2) << "\n"; // 12.5664
    cout << finance::area(2)  << "\n"; // 4
}
⚠️ Never put using namespace std; in a header file

Header files get pasted into every file that includes them. A using namespace std; in a header silently pollutes the namespace of the entire project — and can create name clashes with std::count, std::distance, std::swap, and more. Keep it inside .cpp files only, and prefer std:: prefixes in serious code.

2.6 Comments

// Single-line comment — runs to end of line

/* Multi-line comment
   spans several lines
   but does NOT nest */

int x = 10; // trailing comment

Write comments that explain why, not what. The code already says what it does.

// BAD: restates the code
x = x + 1; // add one to x

// GOOD: explains intent and non-obvious reasoning
// Retry once because the sensor occasionally returns a stale reading
reading = readSensor();

3. Variables & Data Types

3.1 The Mental Model: Named Boxes in Memory

A variable is a named region of memory holding a value of a specific type. The type determines two things: how many bytes are reserved, and how those bytes are interpreted (integer vs. floating point vs. character).

Memory (illustrative):

Address    Content          Variable
0x7ffd10   [ 00 00 00 19 ]  int age = 25;
0x7ffd14   [ 40 8f c2 f5 ]  float price = 1.99f;
0x7ffd18   [ 41 ]           char grade = 'A';
Figure 2 — Variables are typed slots in memory. int age stores 25 as raw bytes; char grade stores 'A' as ASCII code 65. Same memory, different interpretations.

3.3 Declaration, Definition, and Initialization

These three terms are used loosely in casual speech but precisely in C++:

  • Declaration — tells the compiler a name and its type exist: int x;
  • Definition — actually allocates storage: int x; (for variables, declaration is definition).
  • Initialization — gives it an initial value: int x = 5;
// ---- Four ways to initialize ----
int a = 5;        // 1. Copy initialization
int b(5);        // 2. Direct initialization
int c{5};        // 3. Brace (uniform) initialization — PREFERRED
int d{};         // 4. Value initialization → 0

// ---- Uninitialized: DANGEROUS ----
int e;           // contains garbage on the stack!
💡 Prefer brace initialization

int c{5}; is the safest form because it forbids narrowing conversions: int x{3.9}; is a compile error instead of silently becoming 3. It also works uniformly for every type, including containers and classes.

🧨 Pitfall: uninitialized variables

Local variables of built-in types are not zero-initialized. Reading one is undefined behavior — it may be 0, garbage, or anything. Always initialize:

int total;              // ✗ garbage value
int total = 0;          // ✓ explicit
int total{};            // ✓ value-initialized to 0 (best)

3.4 Multiple Variables

3.6 Type Conversion

Implicit conversion happens automatically when types differ. It is often convenient and occasionally catastrophic.

int    i = 42;
double d = i;        // widening: safe, 42 → 42.0
int    j = 3.99;    // narrowing: 3.99 → 3 (truncation, NOT rounding)
bool   b = 42;      // non-zero → true
char   ch = 65;     // ASCII code 65 → 'A'

Explicit conversion (casts) make your intent visible and are strongly preferred:

double pi = 3.14159;

int a = (int)pi;              // C-style cast — avoid, hides intent
int b = static_cast<int>(pi); // ✓ clear, checked, searchable

// Practical: forcing floating-point division
int total = 7, count = 2;
double avg1 = total / count;                              // 3   ✗ integer division!
double avg2 = static_cast<double>(total) / count;          // 3.5 ✓
⚠️ Integer overflow is silent

Signed overflow is undefined behavior — the compiler may assume it never happens and optimize accordingly. Unsigned overflow wraps around predictably (modulo 2ⁿ).

int big = 2147483647;       // INT_MAX
big = big + 1;              // ✗ UNDEFINED BEHAVIOR

unsigned int u = 0;
u = u - 1;                 // ✗ wraps to 4294967295

3.7 char and ASCII

A char is a 1-byte integer that is displayed as a character. The mapping is the ASCII table.

char letter = 'A';
cout << letter << "\n";                        // A
cout << (int)letter << "\n";                   // 65

char next = letter + 1;                      // 'B'
cout << next << "\n";

// Digits to numbers: '7' is 55, so subtract '0'
char digit = '7';
int  value = digit - '0';                       // 7
Output
A 65 B

3.8 Constants

Use const when a value must never change after initialization. It documents intent and lets the compiler optimize.

const double PI = 3.14159265358979;
const int    MINUTES_PER_HOUR = 60;
const int    MAX_USERS = 100;

// PI = 3.14;  // ✗ compile error: assignment to a constant

constexpr is stronger: it guarantees the value is computable at compile time.

constexpr int SQUARE(int n) { return n * n; }
constexpr int SIZE = SQUARE(10);   // computed by the compiler; usable as array size
int buffer[SIZE];                  // valid

3.9 auto — Type Deduction (C++11)

auto asks the compiler to deduce the type from the initializer. It is not "dynamic typing" — the type is fixed at compile time and fully checked.

auto x    = 5;            // int
auto pi   = 3.14;         // double
auto f    = 3.14f;        // float
auto name = string("Ann"); // std::string
auto flag = true;         // bool

// Most valuable with long, awkward types:
auto it = myVector.begin();   // std::vector<int>::iterator
auto m  = std::map<string, int>{};
💡 When to use auto

Use it when the type is obvious from the right-hand side (auto count = 0;) or painfully verbose (iterators). Avoid it when it hides a conversion you should think about.

3.10 Naming Rules and Conventions

Hard rules (compiler-enforced):

  • Must begin with a letter or underscore.
  • May contain letters, digits, and underscores only.
  • Cannot be a reserved keyword (int, class, return, …).
  • Case-sensitive: age ≠ Age.
  • Identifiers containing __ or starting with _ + uppercase are reserved for the implementation.

3.11 Complete Beginner Example — "About Me"

This small program uses everything from Sections 2 and 3: output, variables of different types, constants, and type conversion. Read every line and then change the values.

#include <iostream>
#include <string>
using namespace std;

int main() {
    // Declare and initialize variables of different types
    string name  = "Alice";
    int    age   = 25;
    double height = 1.68;         // meters
    char   grade = 'A';
    bool   isStudent = true;

    // A constant that cannot be changed
    const int BIRTH_YEAR = 2000;

    // Print everything on separate lines
    cout << "Name       : " << name << "\n";
    cout << "Age        : " << age << "\n";
    cout << "Height     : " << height << " m\n";
    cout << "Grade      : " << grade << "\n";
    cout << "Student?   : " << (isStudent ? "yes" : "no") << "\n";
    cout << "Birth year : " << BIRTH_YEAR << "\n";

    // Type conversion: double → int truncates
    int heightCm = static_cast<int>(height * 100);
    cout << "Height in cm: " << heightCm << "\n";

    return 0;
}
Output
Name : Alice Age : 25 Height : 1.68 m Grade : A Student? : yes Birth year : 2000 Height in cm: 168

What to try: Change height to 1.689 and see the truncation (168). Change isStudent to false and see the ternary print no. Try assigning a new value to BIRTH_YEAR — the compiler will refuse, proving that const means what it says.

4. User Input & Validation

4.1 Reading with cin

cin ("character input") is the standard input stream. The extraction operator >> reads a value, converts it to the destination type, and skips leading whitespace.

#include <iostream>
using namespace std;

int main() {
    int age;
    cout << "Enter your age: ";
    cin >> age;
    cout << "You are " << age << " years old.\n";
    return 0;
}
Interactive session
Enter your age: 25 You are 25 years old.

4.2 Reading Multiple Values

int width, height;
cout << "Enter width and height: ";
cin >> width >> height;      // space-, tab-, or newline-separated
cout << "Area = " << width * height << "\n";
Interactive session
Enter width and height: 12 8 Area = 96

4.3 The Classic Space Bug: cin >> vs getline

cin >> stringVar stops at the first whitespace. Typing "John Doe" stores only "John".

string name;
cout << "Full name: ";
cin >> name;                 // input "John Doe"
cout << "[" << name << "]\n";
Output
Full name: John Doe [John]

Use getline() to read an entire line:

#include <string>

string fullName;
cout << "Full name: ";
getline(cin, fullName);      // reads everything up to Enter
cout << "Hello, " << fullName << "\n";
Output
Full name: John Doe Hello, John Doe
🧨 The leftover-newline trap

Mixing cin >> and getline is the single most common beginner input bug. cin >> age leaves the '\n' in the buffer; the next getline immediately reads that empty line.

int age;
string name;

cin >> age;                     // user types "25\n" → buffer holds '\n'
cin.ignore();                   // ✓ consume the leftover newline
getline(cin, name);             // now reads the real name

4.4 Validating Input (Professional Practice)

Real programs must assume users type nonsense. When extraction fails, cin enters a fail state and refuses all further reads until you clear it.

#include <iostream>
#include <limits>
using namespace std;

int readInt(const string& prompt) {
    int value;
    while (true) {
        cout << prompt;
        if (cin >> value) {
            // success — but clear the trailing newline for later getline()
            cin.ignore(numeric_limits<streamsize>::max(), '\n');
            return value;
        }
        // failure: clear error flags and discard the bad input
        cin.clear();
        cin.ignore(numeric_limits<streamsize>::max(), '\n');
        cout << "Invalid number. Try again.\n";
    }

8. Switch Statements

8.1 Basic Syntax

switch compares one integral or enum value against a list of compile-time constants. It is clearer and often faster (jump table) than a long if-else if chain.

int day = 4;

switch (day) {
    case 1: cout << "Monday\n";    break;
    case 2: cout << "Tuesday\n";   break;
    case 3: cout << "Wednesday\n"; break;
    case 4: cout << "Thursday\n";  break;   // runs
    case 5: cout << "Friday\n";    break;
    case 6:
    case 7: cout << "Weekend\n";   break;   // intentional fallthrough
    default: cout << "Invalid day\n";
}
Output
Thursday

8.2 Why break Is Mandatory

Without break, control falls through into the next case and keeps executing.

int x = 1;
switch (x) {
    case 1: cout << "one ";     // no break!
    case 2: cout << "two ";     // no break!
    case 3: cout << "three ";   break;
}
cout << "\n";
Output
one two three

Fallthrough is occasionally useful (grouping cases as in day 6/7 above). When intentional, mark it explicitly:

case 'a':
case 'e':
case 'i': cout << "vowel\n"; break;

// C++17 attribute documents intent and silences warnings
case 1:
    initialize();
    [[fallthrough]];
case 2:
    process();
    break;

8.3 Scoping Inside a switch

All cases share one scope, so you cannot declare the same variable name in two cases without braces:

        cout << result;
        break;

    case 2: {

        break;

}

9.8 Complete Beginner Example — "Guessing Game"

This is the friendliest way to understand a while loop. The loop keeps running until the user's guess matches the secret number. Each iteration, the program gives feedback (too high / too low) and counts how many tries it took.

#include <iostream>
#include <cstdlib>   // std::rand, std::srand
#include <ctime>     // std::time
using namespace std;

int main() {
    // Seed the random generator with the current time. Without seeding,
    // rand() produces the same sequence on every run.
    srand(time(nullptr));

    // rand() % 100 gives 0..99, +1 shifts the range to 1..100
    int secret = rand() % 100 + 1;
    int guess  = 0;
    int tries  = 0;

    cout << "I am thinking of a number between 1 and 100.\n";

    while (guess != secret) {          // keep looping until guessed
        cout << "Your guess: ";
        cin  >> guess;
        ++tries;                        // count this attempt

        if      (guess < secret) cout << "Too low.\n";
        else if (guess > secret) cout << "Too high.\n";
        else                     cout << "Correct! You took " << tries << " tries.\n";
    }

    return 0;
}
Interactive session
I am thinking of a number between 1 and 100. Your guess: 50 Too low. Your guess: 75 Too high. Your guess: 62 Too low. Your guess: 68 Correct! You took 4 tries.

Why each piece exists:

  • srand(time(nullptr)) — the seed. Without it, every run produces the same "random" number.
  • rand() % 100 + 1 — maps a huge random integer to the 1–100 range.
  • while (guess != secret) — the sentinel-controlled loop. It keeps going until the condition becomes false.
  • ++tries — short for tries = tries + 1, inside the loop so it runs each iteration.
  • The three-way if/else inside the loop is the feedback engine: it tells the player which direction to adjust.

11.1 Why Functions?

A function is a named, reusable block of code. Functions give you:

  • Reuse — write once, call many times.
  • Readability — calculateTax(amount) is clearer than 15 inline lines.
  • Testability — small functions are easy to verify in isolation.
  • Isolation — local variables cannot leak into other code.

11.8 Recursion

A function that calls itself. Every recursive function needs a base case — without it, you get a stack overflow.

long long factorial(int n) {
    if (n <= 1) return 1;          // base case
    return n * factorial(n - 1);       // recursive case
}

cout << factorial(10) << "\n";          // 3628800

// Tracing factorial(4):
// 4 * factorial(3)
// 4 * 3 * factorial(2)
// 4 * 3 * 2 * factorial(1)
// 4 * 3 * 2 * 1 = 24
🧨 Missing base case
int bad(int n) { return bad(n - 1); }   // ✗ infinite recursion → crash

Each call consumes stack space. A few thousand frames is usually enough to overflow the default stack (1–8 MB), which is why recursion must be shallow or tail-optimized.

11.12 Complete Beginner Example — "Functions Explained Step-by-Step"

This program starts with a working calculation written inline, then refactors it into a function. Seeing both versions side by side is the fastest way to understand what a function actually does.

#include <iostream>
#include <cmath>
using namespace std;

// A function: return type = double, name = circleArea,
// one parameter: radius (a double, passed by value)
double circleArea(double radius) {
    constexpr double PI = 3.14159265358979;
    return PI * radius * radius;
}

// A second function that USES the first
double ringArea(double outer, double inner) {
    return circleArea(outer) - circleArea(inner);
}

int main() {
    double outerR = 10.0;
    double innerR = 6.0;

    // Calling the function twice, with different arguments
    cout << "Outer circle area : " << circleArea(outerR) << "\n";
    cout << "Inner circle area : " << circleArea(innerR) << "\n";
    cout << "Ring area         : " << ringArea(outerR, innerR) << "\n";

    return 0;
}
Output
Outer circle area : 314.159 Inner circle area : 113.097 Ring area : 201.062

Why each piece exists:

  • double circleArea(double radius) — the signature: it promises to return a double and accept one double. The compiler enforces this.
  • constexpr double PI — the constant lives inside the function, so it cannot be accidentally modified elsewhere. This is a form of encapsulation even without classes.
  • return PI * radius * radius; — the value computed here is copied back to the caller.
  • ringArea calls circleArea twice — functions can be composed. This is how large programs are built: small, tested functions calling other small, tested functions.

What to try: Call circleArea from main with the number 0 and -5. Notice that the function does not validate its input — negative radius gives a positive area, which is wrong. Add a check if (radius < 0) return -1.0; inside the function and see how that changes the behaviour. This is your first exposure to the idea that functions must defend against bad input.

12.2 Addresses and Pointers

A pointer is a variable that stores a memory address. Two operators matter:

  • &x — address-of: gives the address of x.
  • *p — dereference: gives the value stored at the address in p.
int  x = 10;
int* p = &x;        // p stores the address of x

cout << x    << "\n";  // 10                (the value)
cout << &x   << "\n";  // 0x7ffd...         (x's address)
cout << p    << "\n";  // 0x7ffd...         (same address)
cout << *p   << "\n";  // 10                (dereference)

*p = 20;              // modifies x THROUGH the pointer
cout << x    << "\n";  // 20
Output (addresses vary)
10 0x7ffd3e2a1b4c 0x7ffd3e2a1b4c 10 20
Figure 6 — Pointers hold addresses. p stores the location of x. Dereferencing (*p) follows that address to read or write the value.

12.3 nullptr — The Safe Null Pointer

int* p = nullptr;     // points at nothing

if (p != nullptr) {
    cout << *p << "\n";  // only safe because of the check
} else {
    cout << "p is null\n";
}

// Dereferencing nullptr → undefined behavior (usually a crash)
// cout << *p;   // ✗ NEVER do this
📘 nullptr vs NULL vs 0

Pre-C++11 code used NULL (a macro for 0) which causes overload-resolution surprises. nullptr has its own type std::nullptr_t and converts only to pointers. Always use nullptr.

12.7 Dynamic Memory: new and delete

// Single object

// Array

⚠️ The three classic memory bugs
  • Memory leak: new without delete — memory is never returned.
  • Dangling pointer: using a pointer after delete.
  • Double free: calling delete twice on the same pointer.
int* p = new int(5);
delete p;
// cout << *p;   // ✗ dangling: reading freed memory
// delete p;    // ✗ double free: crash or heap corruption

12.8 Smart Pointers — The Modern Solution

Smart pointers own heap memory and free it automatically. This is how modern C++ handles dynamic memory.

// unique_ptr to an array

arr[0] = 99;

// shared_ptr: reference-counted shared ownership
auto a = std::make_shared<string>("shared");

// freed when the last shared_ptr goes out of scope

publicAnywhere

Encapsulation means hiding internal state and exposing only a controlled interface. This prevents invalid states.

class BankAccount {
private:
    double balance;          // cannot be modified directly
    string owner;

public:
    BankAccount(string o, double initial)
        : owner{o}, balance{initial} { }        // member initializer list

    double getBalance() const { return balance; }
    string getOwner()   const { return owner;   }

    // Mutators with validation — this is the whole point of encapsulation
    void deposit(double amount) {
        if (amount <= 0) { cout << "Invalid deposit\n"; return; }
        balance += amount;
    }

    bool withdraw(double amount) {
        if (amount <= 0 || amount > balance) return false;
        balance -= amount;
        return true;
    }
};
📘 Why the member initializer list?

BankAccount(string o, double i) : owner{o}, balance{i} { } initializes members directly. Assigning inside the body (owner = o;) first default-constructs each member and then assigns — wasteful, and impossible for const members or references. Prefer the initializer list.

13.4 Constructors and Destructors

class Resource {
private:
    int* data;

public:
    // Default constructor
    Resource() : data{new int[100]} {
        cout << "Resource acquired\n";
    }

    // Parameterized constructor
    Resource(int size) : data{new int[size]} {
        cout << "Resource of " << size << " acquired\n";
    }

    // Destructor — runs automatically when the object dies
    ~Resource() {
        delete[] data;
        cout << "Resource released\n";
    }
};

void demo() {
    Resource r(50);     // constructor
}                        // destructor runs at the closing brace
Output
Resource of 50 acquired Resource released

This automatic acquire/release pattern is called RAII (Resource Acquisition Is Initialization) — the single most important C++ idiom. It is how std::vector, std::string, std::fstream, and smart pointers guarantee leak-free behaviour.

13.5 Inheritance

class Animal {
protected:                       // visible to derived classes
    string name;

public:
    Animal(string n) : name{n} { }

    void eat() const { cout << name << " is eating.\n"; }

    // virtual → derived classes MAY override
    virtual void speak() const { cout << "...\n"; }

    // virtual destructor — MANDATORY for polymorphic base classes
    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    Dog(string n) : Animal{n} { }     // call base constructor

    void speak() const override {        // 'override' catches typos
        cout << name << " says: Woof!\n";
    }

    void fetch() const { cout << name << " fetches the ball.\n"; }
};

class Cat : public Animal {
public:
    Cat(string n) : Animal{n} { }
    void speak() const override { cout << name << " says: Meow!\n"; }
};
Figure 8 — Inheritance and polymorphism. Dog and Cat inherit name and eat() from Animal, and each provides its own speak(). A base-class pointer calls the right version at runtime.

13.6 Polymorphism

One interface, many behaviours. Through a base-class pointer or reference, the correct derived method is called at runtime.

int main() {
    Dog d("Rex");
    Cat c("Whiskers");

    d.eat();      // inherited method
    d.speak();    // Dog's version
    d.fetch();    // Dog-only method

    // Polymorphism through a base pointer
    Animal* zoo[] = { &d, &c };
    for (Animal* a : zoo)
        a->speak();   // virtual dispatch picks the right method
}
Output
Rex is eating. Rex says: Woof! Rex fetches the ball. Rex says: Woof! Whiskers says: Meow!
⚠️ Always give polymorphic base classes a virtual destructor
class Base { public: virtual ~Base() = default; };
class Derived : public Base { public: ~Derived() { /* frees memory */ } };

Base* p = new Derived;
delete p;   // without a virtual destructor, Derived's destructor is NEVER called → leak

13.7 Abstract Classes and Interfaces

A pure virtual function (= 0) has no implementation and makes the class abstract — it cannot be instantiated. Derived classes must implement it.

class Shape {
public:
    virtual double area()      const = 0;   // pure virtual
    virtual double perimeter() const = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape {
    double r;
public:
    Circle(double radius) : r{radius} { }
    double area()      const override { return 3.14159265 * r * r; }
    double perimeter() const override { return 2 * 3.14159265 * r; }
};

class Rectangle : public Shape {
    double w, h;
public:
    Rectangle(double width, double height) : w{width}, h{height} { }
    double area()      const override { return w * h; }
    double perimeter() const override { return 2 * (w + h); }
};

13.8 Static Members

static members belong to the class, not to any individual object.

class Counter {
private:
    static int total;            // shared by all Counter objects

public:
    Counter()  { ++total; }
    ~Counter() { --total; }

    static int getTotal() { return total; }   // no object needed
};

int Counter::total = 0;      // definition required outside the class

Counter a, b, c;
cout << Counter::getTotal() << "\n";   // 3

13.9 Operator Overloading

class Vector2 {
public:
    double x, y;

    Vector2(double x_ = 0, double y_ = 0) : x{x_}, y{y_} { }

    // Addition operator
    Vector2 operator+(const Vector2& other) const {
        return Vector2(x + other.x, y + other.y);
    }

    // Stream output operator (must be a free function)
    friend ostream& operator<<(ostream& os, const Vector2& v) {
        os << "(" << v.x << ", " << v.y << ")";
        return os;
    }
};

#include <string>
#include <vector>
#include <stdexcept>
using namespace std;

class BankAccount {
private:
    string              owner;
    double              balance;
    vector<string>      history;

    void log(const string& entry) { history.push_back(entry); }

public:
    BankAccount(string o, double initial = 0.0)
        : owner{o}, balance{initial} {
        if (initial < 0) throw invalid_argument("Negative initial balance");
        log("Account opened");
    }

    const string& getOwner() const { return owner; }

        if (amount <= 0) throw invalid_argument("Deposit must be positive");

    }

        if (amount <= 0)               throw invalid_argument("Withdrawal must be positive");
        if (amount > balance)             return false;

        return true;
    }

    void printHistory() const {
        cout << "--- " << owner << "'s history ---\n";
        for (const string& h : history) cout << "  " << h << "\n";
        cout << "Balance: $" << balance << "\n";
    }
};

An anonymous, inline function. Invaluable for callbacks and algorithms.

// Capturing outer variables

cout << "Above 10: " << count << "\n";   // 2

// [&] captures by reference, [=] by value, [&x] just x
std::sort(nums.begin(), nums.end(),
           [](int a, int b) { return a > b; });   // descending

for (int n : nums) cout << n << " ";            // 22 15 9 7 3

14.9 Move Semantics (Conceptual)

Copying a large vector duplicates every element. Moving transfers ownership of the internal buffer, leaving the source empty — an O(1) operation.

vector<int> makeBig() {
    vector<int> v(1000000, 7);
    return v;               // moved out, not copied (NRVO / move)
}

vector<int> a = makeBig();          // efficient
vector<int> b = std::move(a);         // explicit move; a is now empty
📘 Why this matters

Before C++11, returning a large vector from a function meant copying a million integers. Move semantics made this effectively free, which is why modern C++ code passes and returns containers freely.

15. Exception Handling & File I/O

15.1 Why Exceptions?

Function return values can signal errors, but they are easy to ignore and they clutter the happy path. Exceptions separate the error-handling path from the normal path.

// Without exceptions: every call site must check
int code = readFile("data.txt", buffer);
if (code == -1) { /* handle */ }
else if (code == -2) { /* handle */ }
// ...forgot to check one → silent bug

// With exceptions: the error propagates to whoever can handle it
try {
    readFile("data.txt", buffer);
} catch (const std::exception& e) {
    cout << "Error: " << e.what() << "\n";
}

15.2 throw, try, catch

#include <stdexcept>

double divide(double a, double b) {
    if (b == 0)
        throw std::invalid_argument("Division by zero");
    return a / b;
}

int main() {
    try {
        cout << divide(10, 2) << "\n";    // 5
        cout << divide(10, 0) << "\n";    // throws
        cout << "never reached\n";
    }
    catch (const std::invalid_argument& e) {   // catch by const reference
        cout << "Caught: " << e.what() << "\n";
    }
    catch (const std::exception& e) {           // generic fallback
        cout << "Std exception: " << e.what() << "\n";
    }
    catch (...) {                                   // catches anything
        cout << "Unknown error\n";
    }
}
Output
5 Caught: Division by zero

#include <sstream>

while (getline(in, line)) {
    if (firstLine) { firstLine = false; continue; }   // skip header

    istringstream iss(line);
    string name, ageStr, scoreStr;

    if (getline(iss, name,     ',') &&
        getline(iss, ageStr,   ',') &&
        getline(iss, scoreStr, ',')) {

        try {
            int    age   = stoi(ageStr);
            double score = stod(scoreStr);
            cout << name << " is " << age << " with score " << score << "\n";
        } catch (const std::exception& e) {
            cerr << "Malformed record: " << line << "\n";
        }
    }
}

16.8 Why C++ Specifically?

Three properties explain almost every item in the lists above:

  1. Zero-cost abstractions. A C++ class or template compiles down to code that is as fast as hand-written C. You do not pay a runtime penalty for using high-level features.
  2. Deterministic memory management. You decide when memory is allocated and freed. With RAII and smart pointers, this is also safe — resources are released automatically when objects go out of scope. Garbage-collected languages cannot offer the same predictability.
  3. Direct hardware access. C++ lets you manipulate bits, addresses, and device registers. This is why it is used in operating systems, drivers, and embedded firmware, where the code must talk directly to hardware.

B.1 The Debugger Workflow

#   continue            — resume
#   quit                — exit

B.2 Sanitizers — Catch Bugs Automatically

Sanitizers are compiler instrumentation that detects memory and undefined-behaviour errors at runtime. Use them on every project.

# AddressSanitizer: out-of-bounds, use-after-free, leaks
g++ -std=c++17 -g -fsanitize=address main.cpp -o app

# UndefinedBehaviorSanitizer
g++ -std=c++17 -g -fsanitize=undefined main.cpp -o app

# Both together
g++ -std=c++17 -g -fsanitize=address,undefined main.cpp -o app
💡 A bug that ASan finds instantly
int arr[3] = {1, 2, 3};
cout << arr[5];        // without ASan: silent garbage
// with ASan: "stack-buffer-overflow ... READ of size 4" + exact line number

B.3 Debugging Strategies

  • Reproduce reliably. A bug you cannot reproduce cannot be fixed.
  • Bisect. Comment out half the code; narrow down which half contains the bug.
  • Print early, print often. Temporary cout statements remain the fastest debugging tool.
  • Check assumptions. The bug is almost always where you were certain there was none.
  • Read the error bottom-up. Compiler errors often list the root cause last.
  • Rubber-duck it. Explain the code line by line to an inanimate object; you will find the bug.

Appendix D — Best Practices Checklist

D.1 Variables & Types

  • Initialize every variable at the point of declaration.
  • Prefer brace initialization int x{5}; — it blocks narrowing.
  • Use const for values that never change; constexpr for compile-time constants.
  • Use double rather than float unless memory is genuinely constrained.
  • Never compare floating-point values with ==.
  • Use size_t (or std::size_t) for sizes and indices.

D.2 Control Flow

  • Always use braces, even for single-statement bodies.
  • Order if-else if chains from most to least restrictive.
  • Never forget break in a switch (unless fallthrough is intended — and then mark it).
  • Prefer range-based for when iterating whole containers.
  • Guard loop bounds: use i < size, never i <= size.

D.3 Functions

  • Keep functions small and single-purpose (roughly ≤ 30 lines).
  • Pass large objects by const&.
  • Mark read-only member functions const.
  • Avoid global mutable state.
  • Use nullptr, never NULL or 0.

D.4 Memory & Resources

  • Prefer std::vector / std::string over raw arrays.
  • Never write new/delete — use smart pointers.
  • Follow RAII: let destructors release resources.
  • Give polymorphic base classes a virtual destructor.
  • Compile with sanitizers during development.

D.5 Code Quality

  • Compile with -Wall -Wextra -Werror; fix all warnings.
  • Use names that describe meaning, not type (totalPrice, not dbl).
  • Comment the why, not the what.
  • Keep functions and variables as local in scope as possible.
  • Format consistently (use clang-format).
