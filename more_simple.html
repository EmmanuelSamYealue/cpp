C++ Complete Course — Everything Explained

This guide assumes you know nothing about programming. Every single word will be explained. If you have never written a line of code, this is for you.

🧭 How to use this guide

Read slowly. Do not skip. Type every code example yourself — even typing is practice. If you do not understand a word, it is explained somewhere in these pages. Use Ctrl+F (or Cmd+F on Mac) to search for it.

Remember: everyone who programs today was once a beginner who did not understand any of this. Struggling is normal. It is not a sign of failure — it is a sign of learning.

Before You Start — Absolute Basics

This section covers things experienced programmers assume you already know. Read it once. If anything sounds obvious, skip ahead.

What is a computer, in one paragraph?

A computer is a machine that follows instructions. It has no imagination. It cannot guess what you mean. It just does exactly what it is told, step by step, in the order it is told. If you say "make a sandwich" it will sit there forever, because it does not know what a sandwich is. You have to tell it every single step. Programming is the act of writing those steps in a language the computer can follow.

What is a "program"?

A program is a list of instructions in a file. When you open a program (a game, a browser, a calculator), the computer reads the file and does each instruction, one by one. A program is nothing more than a very detailed, very specific recipe.

What is "code"?

Code is the text you type that becomes a program. Code is written in a language (C++ in our case) — just like a recipe can be written in English or French. The computer cannot read C++ directly; it reads a lower-level language, so we need a helper tool (a compiler) to translate.

What is a "compiler"?

A compiler is a translator program. You give it your C++ code (text) and it gives you back a program the computer can run. Think of it as Google Translate, but for code. When you "compile", you run the translator.

What is a "file"?

A file is a box of information on your computer. It has a name (like myfile.cpp) and lives in a folder. A file with the ending .cpp contains C++ code. A file with ending .exe (Windows) or no ending (Mac/Linux) is a runnable program.

What is a "text editor"?

A text editor is a program for typing plain text. Notepad on Windows is a text editor. VS Code is a text editor. When you write code, you use a text editor. You never use Word — Word adds invisible formatting that breaks code.

What is a "terminal" or "command line"?

A terminal is a black window where you type commands instead of clicking buttons. You might not need it if you use an IDE (explained below), but many instructions online assume it. On Windows it is called Command Prompt or PowerShell. On Mac/Linux it is called Terminal.

What is an "IDE"?

An IDE (Integrated Development Environment) is a program that bundles everything you need — the text editor, the compiler, and a debugger — into one window. You click one button and it compiles and runs your code. For absolute beginners, using an IDE is easier than setting everything up manually. We will use Code::Blocks in this course (explained in Section 0).

What is "debugging"?

When your program does not work, you "debug" it. The word comes from the early days of computing when insects (bugs) would physically get stuck inside machines. Today it just means "finding the mistake in your code." A debugger is a tool that helps you find the bug.

What is a "bug"?

A bug is a mistake in the code. There are three kinds:

  1. Syntax errors — you wrote something the computer cannot understand, like pritn instead of print. The compiler catches these and refuses to run your program.
  2. Runtime errors — your program starts but crashes halfway. Like dividing by zero.
  3. Logic errors — your program runs fine but gives the wrong answer. The hardest kind, because nothing tells you anything is wrong.

What is "run"?

"To run" a program means to start it. When you double-click a game and it opens, you ran it. When a compiled program executes, it runs.

What is a "variable"? (a preview)

A variable is a named box. You put a value in the box, and later you can look at what is inside, or replace it with a new value. We will use this idea constantly, so let it sink in now. Think of a jar labelled "sugar" with sugar inside — that is a variable.

What is "memory"? (a preview)

Your computer has two kinds of memory that matter for programming:

  • Disk (also called storage) — where files live when the computer is off. Big, slow, permanent.
  • RAM (also called memory) — where programs live while they are running. Small, fast, temporary. Every variable sits inside RAM.

When you save a file, it goes to disk. When you run a program, it loads into RAM. When you close the program, RAM is wiped. That is why unsaved work disappears when the power goes out.

What is an "operating system"?

An operating system (OS) is the master program that runs the whole computer: Windows, macOS, or Linux. Your code runs on top of the OS, and the OS handles things like files, memory, and the screen so you do not have to.

What is "syntax"?

Syntax means "grammar rules." Just as English has rules (subject, verb, object), C++ has rules for how you write things. If you break the rules, the compiler refuses to translate your code. You will see many syntax errors. They are normal.

What does "compile" mean as a verb?

"To compile" = to run the compiler on your code. This is the step that turns your text into a program. Until you compile successfully, your program cannot run.

What is "source code" vs "executable"?

  • Source code — the text you wrote. Human-readable. Ends in .cpp.
  • Executable — the compiled program. Machine-readable. Ends in .exe on Windows, no special ending on Mac/Linux.

What is an "algorithm"?

An algorithm is a series of steps to solve a problem. A recipe is an algorithm. Directions to a friend's house are an algorithm. You will write thousands of small algorithms in your life as a programmer.

What is "input" and "output"?

  • Input — anything the program receives from the outside: what the user types, a file being read, a click of a mouse.
  • Output — anything the program sends out: text on the screen, a file saved, a sound played.
💡 You now know enough to start

You now understand what a program is, what code is, what a compiler is, what a variable is, and what a bug is. Those are the key concepts. Everything else in this course builds on them.

📘 How to read a compiler error

Compiler errors look scary but always have the same shape:

file.cpp:LINE:COL: error: MESSAGE
  • file.cpp — which file contains the problem.
  • LINE — which line. Always look one line above too — a missing semicolon is reported on the next line.
  • error: — stops compilation. warning: — legal but suspicious. During learning, treat warnings as errors.

1. Introduction to C++

1.1 What Is Programming?

🥪 Picture this

Imagine you are teaching a very young child to make a peanut-butter sandwich. The child does not know anything yet. You cannot just say "make a sandwich" — you must break it into tiny steps:

  1. Pick up a slice of bread.
  2. Open the peanut butter jar.
  3. Spread peanut butter on the bread.
  4. Pick up the second slice.
  5. Put the second slice on top of the first.
  6. You are done.

That numbered list is a program. The abstract logic — "how do you make a sandwich?" — is the algorithm. The language you speak to give the steps (English here, C++ in reality) is the programming language.

Now imagine you forget step 1. What happens? The child tries to spread peanut butter with no bread. Everything goes wrong. This is exactly what happens when you forget a step in code. The computer does not guess. It does not help. It just fails.

Programming involves three skills, in this order:

  1. Breaking a problem into small steps. (Most important.)
  2. Writing each step precisely (loops, conditions, data).
  3. Using the right grammar of the language (syntax). This is the easiest part — but it is the part beginners worry about most.

1.2 What Is C++?

C++ is one of the most widely used programming languages in the world. It was created by Bjarne Stroustrup at Bell Labs starting in 1979, originally as "C with Classes." It is:

  • Cross-platform — runs on Windows, macOS, Linux, phones, embedded chips.
  • Compiled — a compiler turns your source into machine code before it runs.
  • Statically typed — every variable has a fixed type the compiler checks.
  • Multi-paradigm — supports procedural (like C), object-oriented, generic (templates), and functional styles.

It gives you very high-level control over system resources and memory.

1.3 Why Use C++?

  • Performance: Zero-cost abstractions — high-level constructs compile to code as fast as if you had hand-written it.
  • Deterministic memory management: you decide exactly when memory is allocated and freed. RAII makes this safe.
  • Portability: compilers exist for almost every CPU and OS.
  • Object-oriented: gives clear structure to programs and allows code reuse, lowering development cost.
  • Strong fundamentals: teaches memory management, how computers actually work, and supports both procedural and OOP styles.
  • Huge ecosystem: decades of libraries, engines, and tools.
  • Close to C, C#, and Java: programmers can move between these languages easily.

1.4 Difference Between C and C++

C++ was developed as an extension of C, and both languages have almost identical syntax. The main difference is that C++ supports classes and objects, while C does not. That one addition — object-oriented programming — is what gives C++ its name and its power for large systems.

When you launch Fortnite, the Unreal Engine rendering tens of millions of triangles per second is C++. When a trading firm executes an order in 8 microseconds, that path is C++. When Photoshop filters a 500-megapixel image, the pixel loops are C++. The reason is always the same: predictable, low-level control over memory and CPU.

Every C++ program has four parts: header files (like <iostream>), the main() function, statements, and a return value. Once you can spot these four parts, you can read any C++ source file.

1.7 Compiling It

# GCC / Clang
g++ -std=c++17 -Wall -Wextra -O2 myfirstprogram.cpp -o app
./app

# MSVC
cl /EHsc /std:c++17 myfirstprogram.cpp

💡 Always compile with warnings enabled

-Wall -Wextra (GCC/Clang) or /W4 (MSVC) turns on warnings that catch real bugs: unused variables, signed/unsigned mismatches, uninitialized values. During learning, treat warnings as errors with -Werror.

⚠️ Three rules that break beginners most often
  • Case sensitivity: cout, Cout, and COUT are three different names. Only the first exists. if is lowercase; If or IF will produce an error.
  • Semicolons: Every statement ends with ;. #include lines, function definitions, and block braces do not. Forgetting a semicolon produces error: expected ';' before 'return'.
  • White space: The compiler ignores white space. Extra blank lines exist purely for humans — use them to make your code readable.

2.2 Statements — One Instruction at a Time

A computer program is a list of instructions the computer runs. In code, these are called statements. This one tells the computer to print "Hello World" to the screen:

cout << "Hello World!";   // ✓ semicolon ends the statement

Every statement must end with a semicolon ;. If you forget it, you get an error and the program will not compile:

cout << "Hello World!"    // ✗ error: expected ';' before 'return'

Most C++ programs contain many statements. They run one by one, in the same order they are written:

cout << "Hello World!";
cout << "Have a good day!";
return 0;
Output
Hello World!Have a good day!

Notice the two outputs run together with no space or newline. Neither statement adds a line break. This is the #1 reason beginners wonder why their output looks squashed. We fix it next.

2.3 Printing Output with cout — Text

cout plus << outputs values and text. Text must be wrapped in double quotes:

#include <iostream>
using namespace std;

int main() {
    cout << "Hello World!";
    return 0;
}
Output
Hello World!

You can use many cout statements — but remember that cout does not add a newline on its own (as we saw above). You can also chain values in one statement:

int    age   = 25;
double price = 19.99;
string name  = "Alice";

cout << "Name: " << name
     << " | Age: " << age
     << " | Price: " << price << endl;
Output
Name: Alice | Age: 25 | Price: 19.99

2.4 Printing Numbers

To print numbers, do not use quotes. Numbers are written bare:

#include <iostream>
using namespace std;

int main() {
    cout << 3;
    return 0;
}
Output
3

You can also do math right inside cout:

cout << 3 + 3;   // prints 6
cout << 2 * 5;   // prints 10
Output
610

Again, the numbers run together because there is no newline between them. Next section fixes this.

2.5 New Lines

To insert a new line, use \n:

cout << "Hello World! \n";
cout << "I am learning C++";
Output
Hello World! I am learning C++

You can also put \n in its own << chunk:

cout << "Hello World!" << "\n";
cout << "I am learning C++";
💡 Two \n characters create a blank line
cout << "Hello World!" << "\n\n";
cout << "I am learning C++";
Output
Hello World! I am learning C++

Another way: the endl manipulator

endl also inserts a newline:

cout << "Hello World!" << endl;
cout << "I am learning C++";

Both \n and endl break lines. \n is more common. The difference: endl also flushes the output buffer, forcing an immediate write to the OS. Useful before prompts, but slower inside loops.

What is \n exactly? It's an escape sequence — a special two-character code that means "newline." It tells the cursor to move to the start of the next line.

2.7 Namespaces — Why They Exist

Large projects inevitably produce name collisions: your print() and a library's print(). A namespace is like a surname: "Alice Smith" and "Alice Jones" are clearly different people. Every standard library name lives inside the namespace std.

namespace geometry {
    double area(double r) { return 3.14159 * r * r; }
}

namespace finance {
    double area(double r) { return r * r; }
}

int main() {
    cout << geometry::area(2) << "\n"; // 12.5664
    cout << finance::area(2)  << "\n"; // 4
}

Omitting the namespace

You might see C++ programs that skip using namespace std;. Instead they write std:: before each name:

#include <iostream>
// using namespace std;  ← removed

int main() {
    std::cout << "Hello World!";
    return 0;
}

For small programs, using namespace std; is convenient. For larger code, prefer explicit std:: qualification.

⚠️ Never put using namespace std; in a header file

Header files get pasted into every file that includes them. A using namespace std; in a header silently pollutes the namespace of the entire project — and can clash with std::count, std::distance, std::swap, and more. Keep it inside .cpp files only.

2.8 Comments

Comments explain your code to humans — and to future-you. The compiler ignores them. They are also useful for temporarily disabling code while testing.

Single-line comments

Start with two forward slashes (//). Everything after // on that line is ignored:

// This is a comment
cout << "Hello World!";

cout << "Hello World!"; // This is also a comment

Multi-line comments

Start with /* and end with */. Everything between is ignored:

/* The code below will print the words Hello World!
   to the screen, and it is amazing */
cout << "Hello World!";

Use // for short comments and /* */ for longer ones.

🫙 Picture this

  • Contents — the current value (25).

3.13 ASCII — The Character Phonebook

What is ASCII?

ASCII (American Standard Code for Information Interchange) is a rulebook that maps characters (letters, digits, punctuation, control codes) to numbers. Think of it as a phonebook that links characters to numbers. Computers do not understand letters directly — they store numbers. ASCII is the oldest and simplest rulebook for "which number means which letter."

The basic idea

ASCII maps characters → numbers from 0 to 127:

  • 'A' → 65
  • 'a' → 97
  • '0' → 48
  • space → 32

When you type A, the computer stores the number 65 (one byte). When it needs to show it, it looks up 65 and displays A.

cout << "Your name is: " << fullName;

You expected "John Doe" but only got "John". For reading whole lines, use getline(). It takes cin first, then the string variable:

🧨 The leftover-newline trap

Mixing cin >> and getline is the single most common beginner input bug. cin >> age leaves the '\n' in the buffer; the next getline reads that empty line instead of your text.

int age;
string name;

cin >> age;                     // user types "25\n" → buffer still holds '\n'
cin.ignore();                   // ✓ consume the leftover newline
getline(cin, name);             // now reads the real name

5.2 Integer Division — The Most Common Math Bug

⚠️ Integer division truncates

When dividing two integers, the result is also an integer. 10 / 3 gives 3 — the decimal part is thrown away (not rounded). If you want decimals, use float or double, like 10.0 / 3.

int x = 10;
int y = 3;
cout << (x / y) << "\n";    // Integer division, result is 3

double a = 10.0;
double b = 3.0;
cout << (a / b) << "\n";    // Decimal division, result is 3.33333
Output
3 3.33333
With whole numbers, 10 divided by 3 gives 3 — the .333 is thrown away. With decimal numbers, it gives 3.33333.

You can force floating-point division without changing the variables by casting:

int total = 7, count = 2;
double avg1 = total / count;                              // 3   ✗ integer division!
double avg2 = static_cast<double>(total) / count;          // 3.5 ✓

if (ptr != nullptr && *ptr > 0) { /* safe: checks ptr before using it */ }
if (denominator != 0 && numerator / denominator > 1) { /* safe: prevents divide by zero */ }

5.8 Operator Precedence

When a calculation has more than one operator, C++ follows order-of-operations rules. Multiplication happens before addition:

int result1 = 2 + 3 * 4;      // 2 + 12 = 14
int result2 = (2 + 3) * 4;    // 5 * 4 = 20

cout << result1 << "\n";
cout << result2 << "\n";
Output
14 20

To make addition happen first, use parentheses: (2 + 3) * 4 gives 20.

Order of operations (highest to lowest)

  1. () — Parentheses
  2. *, /, % — Multiplication, Division, Modulus
  3. +, - — Addition, Subtraction
  4. >, <, >=, <= — Comparison
  5. ==, != — Equality
  6. && — Logical AND
  7. || — Logical OR
  8. = — Assignment

Addition and subtraction run left to right, unless you add parentheses:

int result1 = 10 - 2 + 5;      // (10 - 2) + 5 = 13
int result2 = 10 - (2 + 5);    // 10 - 7 = 3

cout << result1 << "\n";
cout << result2 << "\n";
Output
13 3
💡 Always use parentheses when in doubt

Parentheses always come first. Use them to control order — they also make your code easier to read.

7.2 The if Statement

Use if to run a block of code only if a condition is true:

if (condition) {
    // runs if condition is true
}

Test if 20 is greater than 18:

    cout << "x is greater than y";

x is greater than y

Here x is 20, y is 18, 20 is greater, so the message prints.

7.3 The else Statement

else specifies a block that runs if the condition is false:

if (condition) {
    // true branch
} else {
    // false branch
}
int time = 20;

if (time < 18) {
    cout << "Good day.";
} else {
    cout << "Good evening.";
}
// Outputs "Good evening."
Output
Good evening.

Here time is 20, which is not less than 18, so the condition is false. The else block runs and prints "Good evening". If time had been 15, the first block would have run and printed "Good day".

7.4 The else if Statement

Use else if to add more conditions to check if the first one was false:

if (condition1) {
    // runs if condition1 is true
} else if (condition2) {
    // runs if condition1 false AND condition2 true
} else {
    // runs if both are false
}
int time = 22;

if (time < 10) {
    cout << "Good morning.";
} else if (time < 20) {
    cout << "Good day.";
} else {
    cout << "Good evening.";
}
// Outputs "Good evening."
Output
Good evening.

Here time is 22. 22 is not less than 10, so the first condition is false. 22 is also not less than 20, so the else if is false too. Only the final else block runs. If time had been 14, "Good day" would have printed.

📘 Order matters

The chain stops at the first true condition. Writing if (score >= 70) before if (score >= 90) would make "A" unreachable. Always order from most restrictive to least.

7.5 Short Hand If...Else (Ternary Operator)

There is a short-hand if...else called the ternary operator because it uses three operands. It returns one value if true, another if false:

variable = (condition) ? expressionTrue : expressionFalse;

Instead of:

int time = 20;
if (time < 18) {
    cout << "Good day.";
} else {
    cout << "Good evening.";
}

You can write:

int time = 20;
string result = (time < 18) ? "Good day." : "Good evening.";
cout << result;

Or even inside cout:

int time = 20;
cout << ((time < 18) ? "Good day." : "Good evening.");
Output
Good evening.

Nested ternary (optional)

You can nest ternaries for more than two outcomes, but it gets harder to read:

int time = 22;
string message = (time < 12) ? "Good morning."
               : (time < 18) ? "Good afternoon."
               : "Good evening.";
cout << message;
💡 Use the ternary operator wisely

Use it for short, simple conditions. For longer or more complex logic, a regular if...else is easier to read.

7.6 Nested If

You can place an if inside another if. This is called a nested if. It lets you check one condition only if another is already true:

if (condition1) {
    // code if condition1 is true
    if (condition2) {
        // code if both condition1 and condition2 are true
    }
}
int x = 15;
int y = 25;

if (x > 10) {
    cout << "x is greater than 10\n";
    if (y > 20) {
        cout << "y is also greater than 20\n";
    }
}
Result
x is greater than 10 y is also greater than 20

Combine or reverse conditions with logical operators. These work with if, else, and else if to build more complex decisions.

8. Switch Statements

🍔 Picture this

At a fast-food counter you say "number 2". The cashier looks at a menu and picks the matching item. That is what switch does: pick one code block from a list based on a value. It compares one integral or enum value to a set of compile-time constants, and is often clearer (and faster) than a long if-else if chain.

switch (expression) {
    case x:
        // code block
        break;
    case y:
        // code block
        break;
    default:
        // code block
}

How it works:

  • The switch expression is evaluated once.
  • The value is compared against each case.
  • If there is a match, that block runs.
  • break and default are optional (explained below).

8.1 Weekday Example

Convert a day number to its name:

int day = 4;

switch (day) {
    case 1: cout << "Monday";    break;
    case 2: cout << "Tuesday";   break;
    case 3: cout << "Wednesday"; break;
    case 4: cout << "Thursday";  break;
    case 5: cout << "Friday";    break;
    case 6: cout << "Saturday";  break;
    case 7: cout << "Sunday";    break;
}
// Outputs "Thursday" (day 4)
Output
Thursday

8.2 The break Keyword

When C++ reaches break, it exits the switch. This stops further case-testing. When a match is found and the job is done, break. There is no need for more testing. break saves a lot of execution time because it skips the rest of the switch.

Without break — fall-through

Without break, control falls through into the next case and keeps running:

int x = 1;
switch (x) {
    case 1: cout << "one ";     // no break!
    case 2: cout << "two ";     // no break!
    case 3: cout << "three ";   break;
}
cout << "\n";
Output
one two three

Fall-through is occasionally useful (grouping cases). When intentional, mark it explicitly with [[fallthrough]];.

8.3 The default Keyword

default is the code that runs if no case matches:

int day = 4;

switch (day) {
    case 6: cout << "Today is Saturday"; break;
    case 7: cout << "Today is Sunday";   break;
    default: cout << "Looking forward to the Weekend";
}
// Outputs "Looking forward to the Weekend"
Output
Looking forward to the Weekend

void paint(Color c) {
    switch (c) {
        case Color::Red:   cout << "#FF0000\n"; break;
        case Color::Green: cout << "#00FF00\n"; break;

    }

🔁 Picture this

9.1 while Loop — Check First, Then Run

A while loop checks the condition before each pass:

    // block to be executed

    cout << i << "\n";

9.6 do-while Loop — Run First, Then Check

The do/while variant always runs once before checking the condition, then repeats while true.

do {
    // block to be executed
} while (condition);   // NOTE the semicolon
⚠️ The semicolon after while is required!

do-while is the only loop in C++ that ends with a ; after while (condition). Forgetting it is a compile error.

Standard example

int i = 0;
do {
    cout << i << "\n";
    i++;
} while (i < 5);
Output
0 1 2 3 4

Do not forget i++, or it will be an infinite loop!

Condition is false from the start

Above, the condition i < 5 was true to begin with, so the loop ran multiple times. But what if the condition is false right from the start?

In this example i starts at 10, so i < 5 is false — yet the do/while loop still runs once:

int i = 10;
do {
    cout << "i is " << i << "\n";
    i++;
} while (i < 5);
Output
i is 10
📘 The key difference

do/while always runs at least once, even if the condition is already false. A regular while would skip the loop entirely if the condition is false at the start.

This makes do/while useful when you want something to happen at least once — like showing a message or asking for input.

Practical example: user input

Keep asking the user for a positive number. The loop stops when the user enters 0 or negative:

10. Arrays & Vectors

📦 Picture this

You do not keep 30 separate jars for coins — you keep one jar full of coins. An array is a numbered row of boxes all holding the same type of thing. A vector is the same idea, but it can grow and shrink.

10.1 What is an Array?

Arrays store multiple values in one variable, instead of declaring a separate variable for each value.

To declare an array, write the type, the name, square brackets with a size:

string cars[4];

That is an array of four strings. To fill it, use an array literal — values in curly braces:

string cars[4] = {"Volvo", "BMW", "Ford", "Mazda"};

An array of three integers:

int myNum[3] = {10, 20, 30};

🍳 Picture this

Writing the steps for making coffee every single morning would be exhausting. Instead, write it once on a recipe card called "makeCoffee", then every morning just say "make coffee." That is what a function is: a recipe card for your code.

11.1 What is a Function?

A function is a reusable block of code that performs a task. Functions give you:

  • Reuse — write once, call many times.
  • Readability — calculateTax(amount) is clearer than 15 inline lines.
  • Testability — small functions are easy to verify on their own.
  • Isolation — local variables cannot leak into other code.

11.7 Pass by Value vs Pass by Reference — Critical

📘 Think of it like… photocopy vs original

Passing by value is handing over a photocopy — the function can scribble on it but your original stays safe. Passing by reference is handing over the original document — whatever the function writes goes straight into your copy.

void writeOnCopy(int x)  { x = 999; }   // photocopy → original unchanged
void writeOriginal(int& x) { x = 999; }   // original → variable becomes 999

int score = 10;
writeOnCopy(score);   // score is still 10
writeOriginal(score); // score is now 999

Rule of thumb: small read-only params → by value; large read-only params → by const&; must-modify params → by non-const &.

11.8 Scope

Scope is the region where a variable can be used.

  • Local variables live inside a function — they die when the function ends.
  • Global variables live outside all functions — they live for the whole program.
int globalVar = 100;          // global scope

void demo() {
    int localVar = 10;        // local scope
    {
        int inner = 5;         // block scope
        cout << inner << "\n";
    }
    // cout << inner;   // ✗ ERROR: out of scope
}
⚠️ Avoid global variables

Globals can be modified from anywhere, which makes bugs very hard to trace. Prefer passing data as parameters and returning results. Reserve globals for genuine program-wide constants (constexpr).

11.9 Recursion

Recursion is when a function calls itself. Every recursive function needs a base case — a way to stop. Without it, the function calls itself forever and the stack overflows.

Example: Factorial

int factorial(int n) {
    if (n == 1) return 1;          // base case — STOP
    return n * factorial(n - 1);       // recursive step
}

cout << factorial(10) << "\n";          // 3628800
Output
3628800

Tracing factorial(4):

4 * factorial(3)
4 * 3 * factorial(2)
4 * 3 * 2 * factorial(1)
4 * 3 * 2 * 1 = 24
🧨 Missing base case
int bad(int n) { return bad(n - 1); }   // ✗ infinite recursion → crash

12. Pointers & References

🏠 Picture this

Your friend asks where you live. You cannot give them your whole house — you give them your address: "go to 123 Main St." A pointer is like that address note. It does not hold the value itself, it holds where the value lives. Like a sticky note in your pocket saying "the sugar is on shelf 3."

12.1 The Memory Model

Figure 6 — Where your variables live. Knowing which region a variable lives in explains why local variables "disappear" (stack unwinds) and why forgetting delete leaks memory (heap never shrinks).

12.2 References

A reference is another name for the same variable. It must be initialized when declared, and can never point to a different variable.

int x = 10;
int &ref = x;    // ref IS x

ref = 20;
cout << x << "\n";          // 20
cout << &x    << "\n";       // same address
cout << &ref  << "\n";       // same address
Output

12.3 Pointers

A pointer stores the memory address of another variable. Two operators matter:

  • &x — address-of: gives the address of x.
  • *p — dereference: gives the value stored at the address in p.
int x = 10;
int *p = &x;     // p stores the address of x

cout << x     << "\n";   // 10
cout << p     << "\n";   // address
cout << *p    << "\n";   // 10
Output
10 0x7ffd3e2a1b4c 10

Changing a value through a pointer

*p = 50;
cout << x;    // 50
Output
50

12.4 Pointer Arithmetic

Pointers can move through array elements:

int arr[3] = {10, 20, 30};

cout << *ptr       << "\n";   // 10
cout << *(ptr + 1) << "\n";   // 20
cout << *(ptr + 2) << "\n";   // 30
Output
10 20 30

12.5 Swap Using References

void swapValues(int &a, int &b) {
    int temp = a;
    a = b;
    b = temp;
}

int x = 1, y = 2;
swapValues(x, y);   // now x=2, y=1

12.6 Dynamic Memory: new and delete

Dynamic memory is allocated while the program runs. new allocates; delete frees.

// Single object
int *p = new int;
*p = 25;
cout << *p << "\n";   // 25
delete p;              // free the memory
p = nullptr;           // good hygiene

// Dynamic array
int *arr = new int[5];
arr[0] = 10;
arr[1] = 20;
delete[] arr;           // NOTE the []
⚠️ The three classic memory bugs
  • Memory leak: new without delete — memory is never returned.
  • Dangling pointer: using a pointer after delete.
  • Double free: calling delete twice on the same pointer.

12.7 Smart Pointers — The Modern Solution

Smart pointers own heap memory and free it automatically. This is how modern C++ handles dynamic memory.

#include <memory>

{
    auto p = std::make_unique<int>(42);
    cout << *p << "\n";
}   // memory freed automatically here — no delete needed

auto a = std::make_shared<string>("shared");
auto b = a;                    // reference count = 2
cout << a.use_count() << "\n"; // 2

Never write new or delete in application code. Use std::make_unique, std::make_shared, or containers like std::vector. This eliminates the entire class of memory-leak bugs.

    BankAccount(string o, double initial = 0.0)
        : owner{o}, balance{initial} {
        if (initial < 0) throw invalid_argument("Negative initial balance");
        log("Account opened");
    }

    double getBalance() const { return balance; }
    const string& getOwner() const { return owner; }

    void deposit(double amount) {
        if (amount <= 0) throw invalid_argument("Deposit must be positive");
        balance += amount;
        log("Deposit: " + to_string(amount));
    }

    bool withdraw(double amount) {
        if (amount <= 0) throw invalid_argument("Withdrawal must be positive");
        if (amount > balance) return false;
        balance -= amount;
        log("Withdrawal: " + to_string(amount));
        return true;
    }

    void printHistory() const {
        cout << "--- " << owner << "'s history ---\n";
        for (const string& h : history) cout << "  " << h << "\n";
        cout << "Balance: $" << balance << "\n";
    }
};

int main() {
    BankAccount acc("Alice", 100.0);
    acc.deposit(250.50);
    acc.withdraw(80.0);
    acc.printHistory();
}
Output

16.12 Why C++ Specifically?

Three properties explain almost every item in the lists above:

  1. Zero-cost abstractions. A C++ class or template compiles to code as fast as hand-written C.

B.3 Debugging Strategies

  • Reproduce reliably. A bug you cannot reproduce cannot be fixed.
  • Bisect. Comment out half the code; narrow down which half contains the bug.
  • Print early, print often. Temporary cout statements remain the fastest debugging tool.
  • Check assumptions. The bug is almost always where you were certain there was none.
  • Read the error bottom-up. Compiler errors often list the root cause last.

Appendix D — Best Practices Checklist

D.1 Variables & Types

  • Initialize every variable at the point of declaration.
  • Prefer brace initialization int x{5}; — it blocks narrowing.
  • Use const for values that never change; constexpr for compile-time constants.
  • Use double rather than float unless memory is genuinely constrained.
  • Never compare floating-point values with ==.
  • Use size_t for sizes and indices.

D.2 Control Flow

  • Always use braces, even for single-statement bodies.
  • Order if-else if chains from most to least restrictive.
  • Never forget break in a switch.
  • Prefer range-based for when iterating whole containers.
  • Guard loop bounds: use i < size, never i <= size.

D.3 Functions

  • Keep functions small and single-purpose.
  • Pass large objects by const&.
  • Mark read-only member functions const.
  • Avoid global mutable state.
  • Use nullptr, never NULL or 0.

D.4 Memory & Resources

  • Prefer std::vector / std::string over raw arrays.
  • Never write new/delete — use smart pointers.
  • Follow RAII: let destructors release resources.
  • Give polymorphic base classes a virtual destructor.
  • Compile with sanitizers during development.

D.5 Code Quality

  • Compile with -Wall -Wextra -Werror; fix all warnings.
  • Use names that describe meaning, not type.
  • Comment the why, not the what.
  • Keep functions and variables as local in scope as possible.
  • Format consistently (use clang-format).
